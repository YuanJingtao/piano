# 声音设计：sound-before-symbol 进入考核——出题即发声，纯耳朵通关是预期脚手架

教学法五大体系共识 sound-before-symbol（先声音后符号）通常只落在教学环节，考核默认静音以防"泄题"；本产品反其道而行：训练关卡**出题瞬间即播放目标音高**（和弦题播柱式和弦），全部快答/弹奏关卡统一，用户凭"听音 + 键盘地理"不看谱通关被确认为**预期教学脚手架**（ear-led，降低初学者挫败感），读谱压力由教程页听音环节与谱面呈现承担。备选 A（考核一律静音、听音只留教程页）被否——用户明确选择教学一致性优先于考核纯度；备选 C（默认静音 + "听示范"提示按钮）被否——按需听音会污染 #4 锁定的正确率/响应时间统计口径。实现上仅保留原型 (#5) 的逐关卡内部 `playSound` 钩子，**不做用户可见开关**（首版设置项克制，限时模式是唯一例外，ADR 0003）；若日后出现耳朵依赖，迭代方向是"技巧毕业后的复习轮静音"逼读谱，钩子已留位，属后续迭代非本图范围。同批锁定的声音边界（明确的"不做"）：**节拍器**不做（#5 已否决打拍/时序考核，日后跟弹练习再引入，Tone.js Transport 是现成能力）；**人声唱名音频**不做（成本高、质控难，唱名用文字+简谱对照）；**UI 事件音效**（结算/过关/按钮声）不做（行内文字反馈已锁定，ADR 0002）。MIDI 真琴接入时**作答发声关闭**（真琴原声即反馈，避免采样叠加不齐），示范音保留。
