# 出题与判定在客户端执行；DB 无题表、无技巧/关卡表——代码即 truth，作答以 JSONB 快照持久化

后端职责写着"题库/内容管理"，但 schema 里刻意**没有** Problem、Technique、Level 表：题池是参数化组合空间（88 键 × 双谱号 × 节奏型），物化入库无信息增益，还引入插件变更时的 DB 同步负担；技巧/关卡定义由代码级插件 manifest 持有（见 ADR 0007），运行数据表以 `techniqueId`/`levelId` 字符串引用。**出题（有放回抽样 + 不连出 + 加权错题池）与判定（对错、响应 ms 计时）全部在浏览器端执行，服务端只接收并持久化作答历史**：响应计时天然发生在客户端；单用户产品无防作弊需求；全 TypeScript 栈让前后端共享同一套题型/判定定义；加权错题池"不跨天持久化"（ADR 0004）恰好就是前端内存态。服务端方案的零延迟优势不成立、判定集中化收益为零，被否。作答记录（AnswerRecord）内嵌**题目 JSONB 特征快照**（如 `{type, midi, clef}` / `{type, patternId}`）+ 用户作答 + 对错 + 响应 ms——特征即数据：未来 SR/自适应直接在其上做聚合，错题特征聚合（弱项统计）无需任何 schema 变更。PracticeSession **每轮一条**（重来/复习/限时轮各自独立），行上**反规范化快照当轮参数**（题型、题数、阈值、时限值），插件日后调参不使历史统计口径漂移；**仅结算轮落库**，中途放弃的轮次不留痕——与"分母恒 12/8"的口径（ADR 0004）一致，为不确定的 SR 未来需求付逐题实时写入的复杂度不值，放弃轮暴露的弱项会被下一轮错题加权池再次抓住。关卡进度独立成表（LevelProgress：passed 永久 + best 结算快照），毕业/解锁/个人排行榜全部为派生查询不落库；排行榜排序键与通过判定同口径（正确率降序、中位响应升序 tiebreak），不发明费解的复合分数；全量保留、查询时排序，单用户数据量无清理压力。所有用户数据表带 `userId`（首版 seed 单一用户），以一列成本换掉未来多用户的全表 migration，其余多用户设施一概不建。限时模式超时口径：**超时记为错题（ms 记为时限值）、轮次继续**——超时只是响应最慢的一种错题，轮次终止会发明第二种结算路径；时限值由关卡 manifest 声明，与"内容即难度参数"的教学立场一致。
