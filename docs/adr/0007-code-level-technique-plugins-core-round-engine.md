# 技巧插件 = 代码级目录 + 窄接口；ADR 0004 的流程规则全部集中在核心 Round 引擎，插件不含流程逻辑

"技巧插件化"刻意**不是**运行时插件系统，也不是 DB 配置驱动：一个技巧 = 一个代码目录（manifest：id、主线/支线归属、prerequisites、关卡定义含题型/题数/阈值/时限/题池采样空间；MDX 教程页：长文内嵌核心提供的共享交互组件——键盘图、VexFlow 谱例、发声按钮；窄接口实现），核心经**静态注册表**加载，新增技巧 = 新增目录 + 注册表一行，核心零改动。DB 配置驱动方案被否：六技巧出题形态差异大（音位快答 / 弹奏判定 / 节奏选择匹配），通用参数化引擎必然过度抽象；单用户本地 Docker 部署没有"运行时热加技巧"的真实场景；代码目录即内容管理（git 版本化）。核心与插件的职责切分是本 ADR 的实质取舍：**轮次题数控制、有放回抽样 + 不连出、加权错题池（3× 权重、答对移出、达标即弃、纯前端内存态）、逐题记录、轮末结算与阈值判定、落库**——这些 ADR 0002/0003/0004 锁定的产品级流程规则全部写进核心通用 Round 引擎（六技巧共享，写一次）；插件只实现四个内容差异点：**题池采样空间（供核心抽取）、题目渲染（谱面/选项）、作答交互（琴键点击/选项选择/MIDI 输入）、判定（answer → ok + 行内反馈内容）**。流程规则若下放到各插件分别实现，规则漂移只是时间问题；窄接口用 TypeScript 类型在核心定义，类型即插件契约。教程页阅读状态不追踪，技巧解锁即可读；解锁/毕业状态运行时从 LevelProgress 与 manifest prerequisites 派生（关卡内线性、技巧间按主线/支线声明），不落库。
